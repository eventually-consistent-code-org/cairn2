A `ledger_append kind:"evidence"` line for a taskRef that already has a `[x]` closure line RETRACTS that closure: verify rule 4c and distill_manifest list the closure under `superseded` and the phase reads the issue as open while the tracker has it closed, so /cairn:verify fails. Never use an evidence line to record a late close receipt or correct a closure's actuals — append a second `kind:"close"` line (closure lines refuse `note`; put the correction in `summary`). The old closure stays under superseded; that is expected. Companion gotcha: a `stale-audit` flag whose stamped commit is a release bump is a false positive worth a verbatim re-stamp, but one whose `git diff --stat <stamp>..HEAD` touches hooks/guards/server is genuine and needs a real `/cairn:audit security` before verify can pass (phase 26: 12 code commits past security-25-7 at eab2b60 → security-26 at 876d223).
