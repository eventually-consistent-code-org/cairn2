# Review corpus — ADR 0012's own test

ADR 0012 keeps the seat-finding dedup engine until "one call can produce
the whole panel's findings already merged, matching this engine's output
on a recorded corpus". This directory is that corpus and the two arms
that run over it (issue #334). It is a sibling of `evals/`, not a child:
`claude plugin eval` discovers cases recursively under its eval dir, and
twenty-two review sessions must never join the default (CI) run. Select
it with `--eval-dir evals-corpus`.

## Shape

```
evals-corpus/
  corpus.json                 the items: fix commit, file, known finding
  NN-<slug>/seats/            case corpus-NN-seats  — /cairn:review corpus/NN-<slug>
  NN-<slug>/native/           case corpus-NN-native — /code-review corpus/NN-<slug> high --max-findings all
  NN-<slug>/default/          case corpus-NN-default — /code-review corpus/NN-<slug> high (the default finding limit, #372)
    case.yaml + graders/      generated by scripts/eval-corpus-cases.mjs (committed, idempotent)
    fixture/ + revert.patch   the files the fix touched, as the fix left them; the fix reversed
    scaffold.sh               builds the workspace repo before the run (needs --scaffold)
  mocks/                      a COPY of evals/mocks, refreshed by the generator (the harness rejects a symlink),
                              with the corpus's own audit_record answer written over it: the main suite's
                              canned record carries someone else's findings, and a reviewer handed those
                              stops to report the tool instead of filing its own
  results/<timestamp>/        aggregate-result.json (gitignored, like evals/results)
```

An item is a real fix commit from this repo's history. The harness runs
each case in an empty, sandboxed workspace that cannot read this repo,
so the diff under review travels with the case: the generator copies the
files the fix touched (tests excluded) as the fix left them, plus the
fix reversed as a patch, and the scaffold commits the copy as `main`,
then the patch on branch `corpus/NN-<slug>`. The branch's merge-base
with main is the fix state itself, so `git diff main...corpus/NN-<slug>`
is exactly the defect the fix removed, at the point in history where it
lived — a revert on top of its own fix always applies, where a revert on
today's main mostly does not (seven of eleven conflicted when this was
first tried). The reviewer sees the touched files whole, not the rest of
the repo. Both commits carry neutral messages ("baseline", "candidate
change") and the fixture leaves out tests and the count-carrying docs a
fix refreshes in passing (README, CHANGELOG, the comparison page): the
first smoke run showed the no-plugin baseline reviewing from the commit
message alone, so the ground truth now lives in the graders and nowhere
the reviewer can read.

Item 11 is the control: a clean change (the help-suffix rename) with no
defect, so a review that invents one is caught.

## Ground truth and the two numbers

Each case carries two LLM graders on the final message:

- `k-NN` — the known defect is named at its file (every item but the
  control). The share of runs that pass it, over the arm, is **recall**.
- `precision` — every finding the review presents as a defect is a real
  defect in that diff; on the control, any defect finding fails. Clarity,
  architecture, test-coverage and style notes are outside the correctness
  axis this corpus scores and are ignored — the native call cannot raise
  them by design, so counting them against the seats would score the
  wrong thing (the first full run did exactly that). Its pass rate is the
  **precision proxy** — the aggregate keeps no transcript, so the count
  of findings raised is not recoverable and the number is a judge's
  verdict per run, stated as such.

`scripts/eval-corpus-score.mjs` turns an aggregate into those two numbers
per arm. Both cases are `capability`-tagged: this corpus informs a
decision, it gates nothing.

A run with no grader results — the shape an API error leaves since Claude Code 2.1.299 — is counted as `errored`, named per case, kept out of both rates, and makes the scorer exit 1; the table says how many of an arm's runs were graded so a rate over one survivor reads as such (#377). The arms keep `Agent` enabled on purpose and do not use the harness's `disallowed_tools` field: the seats arm is a fan-out, and the native and default arms are `/code-review` as shipped. The default arm (#372) is the native call without `--max-findings`, the shape a developer actually runs; `disallowed_tools` is not set on it either, because `/code-review` may fan out internally and constraining that would change the thing under test.

## Running it

Subscription only, as everywhere in cairn (`env -u ANTHROPIC_API_KEY`).
`--scaffold` is required — without it the workspace stays empty and
every review reports there is nothing to diff. `--ablation none` skips
the harness's no-plugin baseline arm, which doubles the runs and answers
a question this corpus does not ask (the native case runs the same
command with or without the plugin). One arm at a time; each run lands
in its own `results/<timestamp>/`. The scorer pools every source it is
given, oldest first, and the latest run of each case is the one scored —
so the two arm directories score as one table, and a rerun of a few
cases (after a corrected ground truth, say) is appended rather than
redone in full. A directory given alone resolves to its latest run:

```bash
env -u ANTHROPIC_API_KEY claude plugin eval . --eval-dir evals-corpus --scaffold --trust-plugin --ablation none \
  --case 'corpus-*-seats'  --runs 1 -j 2 --allow-tools Bash Agent 'mcp__plugin_cairn_cairn__*' --max-cost-usd 15 --no-publish
env -u ANTHROPIC_API_KEY claude plugin eval . --eval-dir evals-corpus --scaffold --trust-plugin --ablation none \
  --case 'corpus-*-native' --runs 1 -j 2 --allow-tools Bash Agent ReportFindings --max-cost-usd 15 --no-publish
env -u ANTHROPIC_API_KEY claude plugin eval . --eval-dir evals-corpus --scaffold --trust-plugin --ablation none \
  --case 'corpus-*-default' --runs 1 -j 2 --allow-tools Bash Agent ReportFindings --max-cost-usd 15 --no-publish
node scripts/eval-corpus-score.mjs evals-corpus/results/<seats timestamp> evals-corpus/results/<native timestamp> evals-corpus/results/<default timestamp> [<rerun timestamp>...]
```

The native arm's `--max-findings all` needs Claude Code 2.1.288 or
later. Both arms score the harness's `with` runs — under `--ablation
none` those are the only runs — so the two review arms compare like
for like.

## Writing the result down

The numbers go into ADR 0012 under "Evidence", dated, with the CLI
version the aggregate records. If the native arm matches or beats the
seats on recall without losing precision, the ADR records the
correctness axis as a delegation candidate for the next major and ADR
0010's byte-identical default fold holds until then. If not, the
sunset clause stands as unmet, with the numbers.
