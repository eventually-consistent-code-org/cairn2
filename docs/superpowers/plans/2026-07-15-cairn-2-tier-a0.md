# Cairn 2.0 — Tier A0: Continuity Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Crash-proof auto-resume (G1) and the token-cost-annotated recall index + timeline (G3). A session killed mid-`work` — crash, compaction, usage cap, `/clear` — resumes at the exact task with zero re-executed work; session start surfaces a byte-stable index of relevant memory cards with per-card fetch costs. Absorbs `waypoint` from Tier B (routing row flips reserved-A0 → live). Spec: `docs/superpowers/specs/2026-07-15-cairn-2-tier-a0-continuity.md`.

**Architecture:** New server module `core/continuity.ts` owns the handoff (write/read/clear with skeleton guard + atomic temp-file rename) and is called write-through from every state-changing MCP tool — the server is the primary writer; hooks only cover gaps. `planning/ledger.ts` appends verified-task lines to git-committed per-phase `LEDGER.md`. `memory/banner.ts` pre-renders the recall index to `~/.cairn/banner/` on card/scope mutation so the SessionStart hook just cats a file. Plugin gains `hooks/hooks.json` + three dependency-free Node scripts (PostToolUse breadcrumb ≤1/60s, PreCompact refresh, SessionStart injection). Five new MCP tools (23 → 28): `continuity_checkpoint`, `continuity_get`, `continuity_clear`, `ledger_append`, `mem_timeline`. Handoff runtime validation is the zod schema (source of truth); `schema/handoff-v1.json` is the committed versioned contract, and a vitest suite validates fixtures against the zod schema in CI (no ajv dependency).

**Tech Stack:** As P0–P4 — TypeScript 5, Node ≥ 20, zod, vitest, better-sqlite3. **No new dependencies** (path hashing via `node:crypto`, matching `indexDbPath`'s existing pattern).

## Global Constraints

- Base branch: `main` (Tier 0 complete). All paths repo-relative.
- **Per-machine state paths** derive exactly like `indexDbPath` (`server/src/memory/index-store.ts:29`): `<homedir>/.cairn/handoff/<basename>-<sha256(resolve(projectDir)).slice(0,16)>.json` and `<homedir>/.cairn/banner/<basename>-<hash16>.md`. Hook scripts recompute the same hash from cwd (`node:crypto`, no deps).
- Handoff fields EXACTLY per spec §1 (version=1, created, source `tool|posttooluse|precompact|waypoint`, project, phase{number,slug}, issue, plan, task{current,title}, tasks_completed[], tasks_remaining[], blockers[], decisions_in_flight[], uncommitted_files[], next_action, notes, partial). zod schema `HandoffSchema` in `core/continuity.ts`; `schema/handoff-v1.json` committed as the contract doc.
- **Skeleton guard:** a write may not replace a handoff whose `task.current` or `next_action` is non-empty with one where both are empty — richness is monotonic between clears. **Unregistered guard:** every server write requires loadable `cairn.json` (reuse `loadConfig`; on `CONFIG_MISSING` skip silently — never scaffold). Hooks: exit 0 silently when no handoff/banner file exists for the cwd hash.
- New `ErrorCode`s EXACTLY: `HANDOFF_INVALID`, `HANDOFF_STALE` (added to `server/src/errors.ts`). Stale = `created` older than 14 days — `continuity_get` returns it flagged, never errors the session.
- Config: `continuity` block in `ConfigSchema` EXACTLY `{ resume: z.enum(["prompt","auto","off"]).default("prompt"), checkpoint: z.boolean().default(true), wipCommits: z.boolean().default(false), recallIndex: z.object({ enabled: z.boolean().default(true), maxCards: z.number().int().positive().default(20) }).default({}) }` with `.default({})` so existing cairn.json files stay valid. Mirror into `templates/cairn.json.example`.
- New tools named EXACTLY: `continuity_checkpoint`, `continuity_get`, `continuity_clear`, `ledger_append`, `mem_timeline`. Total 23 → 28. All use the existing `wrap()` envelope.
- Ledger path: `.cairn/plans/phases/<NN-slug>/LEDGER.md`, append-only, entry format EXACTLY `- [x] <taskRef> — <summary> — commits <base7>..<head7> — <issueId> closed <YYYY-MM-DD>`. Server appends; never rewrites existing lines.
- Banner MUST be byte-stable: no timestamps, cards ordered scope-tightness (issue > phase > project) then card id lexicographic; fetch cost `ceil(body.length/4)` computed at render (no card frontmatter change, no migration). Unit test renders twice against unchanged state and asserts `Buffer.equals`.
- Timeline granularity is honest: cards carry day-precision `created`, index chunks carry ISO `createdAt` — `mem_timeline` orders by what exists and says so in its description; same-day cards tie-break by id.
- Hook scripts: plain `.mjs`, `node:` imports only, single `node` process, target <100ms; PostToolUse throttled to ≤1 write/60s via handoff-file mtime; PreCompact unthrottled; all fire-and-forget (exit 0 on any error — hook failures must be invisible).
- `check-surface.mjs` `SPEC_RESERVED` drops `waypoint` when its row flips live (the (e) check would otherwise fail — this is the intended ratchet behavior).
- Conventional commits; push after every commit; `cd server && npx vitest run && npx tsc --noEmit` green before every commit; `node scripts/check-surface.mjs` green throughout; dist rebuilt + committed in the final task.
