# Cairn 2.0 — Tier F2: Cross-AI Peer Review Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `peers` verb + `peer_list`/`peer_run` tools — codex/opencode/gemini/grok adapters, caps, convergence discipline, outbound leak gate. Spec: `docs/superpowers/specs/2026-07-22-cairn-2-tier-f2-cross-ai.md`.

**Architecture:** One PR, two stages. Stage 1 (Tasks 1–2): `server/src/peers/run.ts` (allow-listed argv templates, stdin input, caps, timeouts) + config `peers` block; both tools registered (60 → 62). Stage 2 (Task 3): `peers` verb + docs + verification.

**Tech Stack:** TypeScript 5, Node ≥ 20 (`child_process.execFile` with stdin), zod, vitest. No new dependencies.

## Global Constraints

- Base branch: `main`. Conventional commits, one per task. Gate: `cd server && npx vitest run && npx tsc --noEmit`; Task 3 adds `node scripts/check-surface.mjs`.
- Tools EXACTLY `peer_list`, `peer_run`; 60 → 62; 60 existing untouched.
- Providers EXACTLY `codex | opencode | gemini | grok`; argv templates are CONSTANTS, input via stdin ONLY, no shell interpolation ever (`execFile`, never `exec`).
- Defaults: `maxInputChars` 200000, timeout 120000ms. Truncation is head-keep + appended marker EXACTLY `[cairn: input truncated at <N> chars]` + `truncatedInput: true`.
- Missing binary / disabled / timeout → PRECONDITION_FAILED (install hint / enable hint / provider+elapsed). Non-zero exit is a RESULT, not an error.
- Config `peers` block: `z.record` over the provider enum only — unknown provider keys rejected; fields `enabled` (default true), `maxInputChars` (positive int, default 200000).
- Unit tests use a stub binary fixture (a small `#!/bin/sh` script written into a tmp dir prepended to PATH for the child process env) — never assume real CLIs.
- check-surface `TOOL_PREFIXES` gains `peer`. Live verbs 35 → 36.
- Dist rebuilt + committed at stage ends (Tasks 2 and 3).

### Task 1: Peer runner + config block

**Files:**
- Create: `server/src/peers/run.ts`
- Modify: `server/src/config.ts` (peers block in ConfigSchema)
- Test: `server/test/peers-run.test.ts` (new), `server/test/config.test.ts` (peers cases appended; existing cases unedited)

**Interfaces (produces):** spec §2 signatures verbatim (`PROVIDERS`, `Provider`, `PeerResult`, `peerList(projectDir)`, `peerRun(projectDir, provider, input, timeoutMs?)`).

**Implementation notes (binding):**
- Templates as a const record: `codex: ["codex", "exec", "-"]`, `opencode: ["opencode", "run", "-"]`, `gemini: ["gemini", "-p", "-"]`, `grok: ["grok", "-p", "-"]` — argv arrays, first element the binary name resolved via PATH by execFile.
- `peerRun`: load config → provider enabled? → resolve on PATH (spawn ENOENT → PRECONDITION_FAILED install hint) → cap-truncate input (+marker/flag) → `execFile(argv[0], argv.slice(1), { timeout, maxBuffer: 10MB })`, write input to child stdin, capture stdout+stderr (stderr appended after a `\n--- stderr ---\n` divider only when non-empty) → on timeout kill, PRECONDITION_FAILED naming provider + elapsed → resolve PeerResult with real durationMs and the child's exitCode (0 on success, non-zero passthrough).
- `peerList`: for each provider — `onPath` (probe PATH via `existsSync` over PATH entries for the binary name; document the Windows non-goal), `enabled`, effective `maxInputChars`.
- PATH probing and spawning must respect a `PATH` passed through env so tests can prepend a stub dir.
- Stub fixture for tests: write `#!/bin/sh\ncat > /dev/null\necho "stub:$0 ok"` (plus variants: sleeper for timeout, exit-3 for passthrough, stdin-length echo for cap proof), chmod 755, prepend dir to PATH via `process.env` manipulation scoped per test.

**Test cases (write concretely):** detection on/off PATH; enabled default true, config false → PRECONDITION_FAILED; cap truncation (tiny cap in a scratch cairn.json: input 100 chars, cap 40 → stub reports 40+marker length, flag true, marker verbatim); timeout (sleeper stub, 200ms timeout → PRECONDITION_FAILED naming provider); missing binary hint; non-zero exit passthrough (exitCode 3, no throw); stderr divider only when non-empty; config schema — unknown provider key rejected, defaults applied.

- [ ] Steps: failing tests → implement (~140 lines) → full suite green (`config.test.ts` pre-existing cases unedited) → commit `feat(server): peer runner — codex/opencode/gemini/grok adapters, caps, timeouts`

### Task 2: Register peer_list + peer_run + stage-end dist

**Files:** Modify `server/src/index.ts`; test `server/test/mcp.test.ts` (62 pin + cases).

- Registrations after the board tools:
```ts
  server.registerTool("peer_list",
    { description: "Detected external AI peer CLIs (codex/opencode/gemini/grok) — on PATH, enabled, input cap",
      inputSchema: {} },
    wrap(() => peerList(dir())));

  server.registerTool("peer_run",
    { description: "Run one external peer CLI with capped stdin input — advisory output, non-zero exit is a result. "
        + "Outbound content leaves the machine; the peers verb leak-scans before calling",
      inputSchema: { provider: z.enum(PROVIDERS),
                     input: z.string().min(1),
                     timeoutMs: z.number().int().positive().optional() } },
    wrap(async (a: { provider: Provider; input: string; timeoutMs?: number }) => {
      const d = dir();
      return peerRun(d, a.provider, a.input, a.timeoutMs);
    }));
```
- mcp cases: 62 pin; peer_list returns all four providers with onPath false in the bare harness; peer_run against a stub staged on PATH inside the harness project (spawn env note: the server child inherits the test's process env — stage the stub dir onto process.env.PATH for the test and restore after).
- [ ] Steps: failing tests → register → full green → `npm run build` → commit `feat(server): peer_list + peer_run tools — 62 total; stage-end dist`
