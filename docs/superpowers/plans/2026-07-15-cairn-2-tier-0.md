# Cairn 2.0 — Tier 0: Trailhead Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One `/cairn <verb>` entrypoint replaces the seven per-verb command files. A `cairn-trailhead` routing skill holds the canonical verb table (11 live verbs, 17 reserved with tier assignments) and per-verb subroutine files loaded only on invocation; old `/cairn:<verb>` forms survive as two-line shims until P5′. Ships cairn2's own plugin manifest so the surface is dogfood-installable, and a surface-conformance check that hard-fails on routing-table/subroutine/tool-reference drift. Spec: `docs/superpowers/specs/2026-07-15-cairn-2-tier-0-trailhead.md`.

**Architecture:** Pure plugin-layer restructure — zero server changes. `commands/cairn.md` parses the verb from `$ARGUMENTS` and delegates to `skills/cairn-trailhead/SKILL.md`, whose routing table maps each verb to `skills/cairn-trailhead/verbs/<verb>.md`. Existing command bodies move into subroutines; shared boilerplate (error posture, precedence rule, batch-questions rule) hoists into SKILL.md and is stated once. `cairn-planning`/`cairn-memory` skills are untouched — they own policy, subroutines own procedure. The conformance check is a Node script (`scripts/check-surface.mjs`) run by `npm test` in CI: it parses the routing table, verifies live-verb ↔ subroutine-file bijection, and validates every `` `tool_name` `` reference in verb docs against the names extracted from `server/src/index.ts` `registerTool("…")` calls.

**Tech Stack:** Markdown (commands/skills), Node ≥ 20 ESM for the check script (no new dependencies). Server untouched.

## Global Constraints

- Base branch: `main` (includes P0–P4 + recovered command surface at `commands/`). All paths repo-relative.
- **Zero server changes.** `server/` is not touched by any task; the 23-tool registry is read-only input to the check script.
- Live verbs EXACTLY: `plan work verify ship status new import remember recall help do` (11). Reserved verbs EXACTLY as the spec's table: `waypoint`(A0) `scout probe draft route summit auto fast resync`(A) `mark retro distill brief tune`(B) `trace`(C) `triage`(D) `basecamp`(F) (17).
- Routing-table row format EXACTLY: `| verb | purpose (one line) | args | verbs/<verb>.md | live\|reserved-<tier> |`. The table is the single registry — `help` renders from it, the check script parses it.
- Subroutine frontmatter EXACTLY three fields: `verb` (string), `args` (string, the argument-hint), `status` (`live`). Reserved verbs get table rows only — creating a `verbs/*.md` for a reserved verb is a conformance failure.
- Shim content EXACTLY (per old command file, keeping its original `description` frontmatter): body replaced by `Moved: run \`/cairn <verb> $ARGUMENTS\` — then execute skills/cairn-trailhead/verbs/<verb>.md with those arguments.` Shims must still work, not just redirect text.
- Migration is move-and-dedupe, NOT rewrite: subroutine procedure steps stay semantically identical to the P4-final command bodies; only boilerplate duplicated across files may hoist to SKILL.md. Tool names in verb docs must match the server registry exactly (`context_get context_set issue_create issue_get issue_update issue_close issue_list plan_scaffold_project plan_scaffold_phase plan_status plan_phase_ensure plan_drift plan_issues_set plan_import plan_unplanned mem_index mem_search mem_stats mem_card_create mem_card_list mem_card_recall` — 21 of 23; `remember`/`recall` subroutines wrap the `mem_*` set per the cairn-memory skill).
- `do` never mutates tracker state without confirmation; unknown verbs route to `help` with the token echoed and a nearest-verb suggestion — never fall through to `do`.
- Conventional commits; each task commits atomically; `cd server && npx vitest run && npx tsc --noEmit` green before every commit (proves server untouched); `node scripts/check-surface.mjs` green from Task 4 onward.
