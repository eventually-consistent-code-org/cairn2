# Multi-Harness Cairn (CRN-71) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cairn runs everywhere the audience is — Grok Build, GitHub Copilot CLI, Codex, Gemini CLI, Cursor, OpenCode — not just Claude Code (CRN-71, broadened). Locked decisions: npm-ready server + `cairn-setup` installer + checked-in adapter trees (ECC's proven shape); wave order Grok+Copilot → Codex+Gemini → Cursor/OpenCode/Zed.

**Architecture:** Cairn's brains already cross harnesses — the MCP server is client-agnostic (all 71 tools over stdio) and the verbs are markdown. The port is three thin layers per harness: (1) MCP wiring (each harness's config format pointing at the server), (2) an instruction spine (`AGENTS.md` cairn fragment, generated from the trailhead registry so it can never drift; `copilot-instructions.md` for GitHub's ecosystem), (3) a command surface where the harness has one (Copilot prompt files, Codex prompts, Gemini TOML commands). Claude-specific pieces (hooks: continuity breadcrumbs, leak guard, cost tracker, observations; plugin manifest) degrade **honestly** per a documented capability table — harnesses with hook runtimes (Cursor, Grok claims one) can pick them up in later waves.

**Key research facts (2026-07-29):**
- Grok Build reads `AGENTS.md`/`CLAUDE.md`, `.mcp.json`, and claims Claude-compatible plugins/hooks/skills — nearest-to-free port, and the validation target for wave 1.
- Copilot CLI: MCP via `~/.copilot/mcp-config.json` (stdio/http/sse), custom agents, headless mode; instruction layer via `.github/copilot-instructions.md` + `.github/prompts/*.prompt.md` (`chat.promptFiles`).
- Codex: `~/.codex/config.toml` `mcp_servers` + `AGENTS.md` + prompts dir. Gemini CLI: `~/.gemini/settings.json` `mcpServers` + `GEMINI.md`. Cursor: `.cursor/mcp.json` + rules + a real hooks runtime. OpenCode: `opencode.json` + `AGENTS.md`.

## Global constraints

- **One generated spine.** `harness/AGENTS-cairn.md` is generated by `scripts/gen-agents.mjs` from the trailhead registry (same pattern as gen-commands); `check-surface.mjs` fails when it drifts. Hand edits go in the generator template, never the output.
- **Honest degradation table.** Every harness row states exactly what works (all 71 tools, verb instructions) and what doesn't (hooks, slash-command ergonomics) — no "supported" hand-waving.
- **The npm publish itself is John's click** (npm auth); everything ships publish-ready (`server/package.json` bin + files), and the installer works from a git clone path until the package is live.
- Installer is dependency-free Node, additive and idempotent: never clobbers an existing MCP config entry — merges or prints the block to add.
