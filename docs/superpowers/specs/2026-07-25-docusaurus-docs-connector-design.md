# Docusaurus docs connector — design

**Date:** 2026-07-25 · **Issue:** CRN-47 · **Status:** approved

## Problem

Cairn's docs publishing (`/cairn:docs publish`) has one connector: Confluence.
Teams whose documentation site is a Docusaurus static site have no way to
publish cairn's docs tree into it. Docusaurus has no runtime page API — it is
a static-site generator whose source of truth is markdown files under a
`docs/` folder — so a second, filesystem-shaped connector is needed.

## Approach (chosen)

A filesystem `DocsConnector` that writes markdown + Docusaurus metadata files
into a local Docusaurus site checkout, following the community-recommended
architecture: files under `docs/`, autogenerated sidebars mirroring the folder
tree, `_category_.json` for folder metadata, front matter for page metadata.
Deployment stays with the user's CI. Optional opt-in auto-commit in the site
repo (never push).

Rejected alternatives:
- **Git URL target** (clone → write → commit → push): credentials, conflicts,
  temp checkouts — not the community pattern, heavy for v1.
- **Docusaurus plugin / remote-content pull**: puts cairn-specific build
  plugins inside the user's site; couples cairn to the site's build.

## Config

```json
{
  "docs": {
    "connector": "docusaurus",
    "config": {
      "sitePath": "../my-docs-site",
      "docsDir": "docs",
      "autoCommit": false
    }
  }
}
```

- `sitePath` (required) — path to the Docusaurus site checkout, absolute or
  relative to the cairn project dir. Must exist and contain a
  `docusaurus.config.js|ts` (sanity probe) → else `CONFIG_INVALID` with the
  path checked in the message.
- `docsDir` (default `"docs"`) — docs root inside the site. Created if
  missing.
- `autoCommit` (default `false`) — after a successful publish, if `sitePath`
  is inside a git work tree: `git add <project dir> && git commit -m
  "docs(cairn): publish <project>"`. Never pushes. Commit failure (or not a
  repo) degrades to a warning in the publish result — it never fails the
  publish.

## Adapter: `server/src/docs/adapters/docusaurus.ts`

Implements `DocsConnector` with the filesystem as the backend.

- **Capabilities:** `{ hasPageTree: true, hasAttachments: false,
  hasLabels: false, hasNativeToc: true }` (see SPI change below).
- **Page identity:** `Page.id` = path relative to `docsDir` (POSIX
  separators). Leaf page → `<parent>/<slug>.md`; directory page → `<parent>/
  <slug>` (the folder). `Page.url` = absolute file path (no site URL is
  knowable without building the site).
- **Naming (amended during verification):** filenames mirror the source —
  `PageSpec.sourceName` (the repo file/dir basename, threaded from
  `DocNode` through the publisher) wins; `slugify(title)` (lowercase,
  alphanumerics kept, everything else collapsed to single hyphens, trimmed)
  is the fallback for pages with no source file (e.g. the project root).
  Mirroring keeps repo-relative links between docs resolving on the
  published site. Paths stay stable on rename: `updatePage` with a new
  title rewrites front matter `title:` but keeps the file path.
- **CommonMark opt-out (amended during verification):** every page's front
  matter carries `mdx: {format: md}` — Docusaurus v3 compiles `.md` as MDX
  by default, where literal `<angle>` text is a parse error; SPI bodies are
  raw markdown, so CommonMark is the correct per-file setting.
- **`ensureRoot(projectName)`** — idempotent: ensures
  `<docsDir>/<slug(projectName)>/` exists with a `_category_.json`
  (`{"label": projectName}`). Returns the folder as the root `Page`. The
  root's landing content (README) arrives via `updatePage(root.id, …)`,
  written as `index.md` in the folder — Docusaurus's native category index.
- **`createPage(spec)`** — leaf: writes `<parent>/<slug>.md` with YAML front
  matter (`title`, `sidebar_position`) followed by the markdown verbatim
  (no format conversion — the SPI already speaks markdown).
  `sidebar_position` = existing sibling count + 1 (publish order).
- **Directory pages** — when `updatePage`/`createPage` target a page that has
  children (publish.ts publishes directories as pages), the adapter stores
  the body as `<folder>/index.md` and maintains `_category_.json`
  (`label`, `position`). A directory page with no markdown gets
  `_category_.json` with `"link": {"type": "generated-index"}` instead of an
  `index.md` — Docusaurus renders the index natively.
- **`findPage(title, parentId)`** — with `parentId`: probe
  `<parent>/<slug>.md` and `<parent>/<slug>/`. Without: recursive search
  under the project root for a matching slug (collisions are impossible per
  directory on a filesystem, so the Confluence-style space-wide title
  disambiguation in `publish.ts` naturally no-ops).
- **`updatePage(id, spec)`** — rewrite front matter + body in place;
  `sidebar_position` preserved from the existing file.
- **`listChildren(parentId)`** — readdir; `.md` files (minus `index.md`) and
  subfolders, as `Page`s.
- **Ownership rule:** everything under `<docsDir>/<project-slug>/` is
  cairn-managed and overwritten on publish. The adapter never touches
  anything outside that folder.
- **Front matter escaping:** titles are YAML-double-quoted with `"` and `\`
  escaped.

## SPI change: `hasNativeToc`

`DocsCapability` gains `hasNativeToc: boolean` — "the backend renders
directory/landing indexes natively; do not append generated TOC markdown."

- Confluence: `false`, fake: `false` (existing behavior byte-identical).
- Docusaurus: `true`.
- `publish.ts` branches: when `hasNativeToc`, `publishNode` skips the
  `dirTocMarkdown` refresh pass and `publishTree` skips appending
  `tocMarkdown` to the README landing page — the sidebar and generated
  indexes replace both.

## Registry

`CONNECTOR_PATHS` in `docs/registry.ts` gains
`docusaurus: "./adapters/docusaurus.js"`. Config validated by the adapter's
zod `configSchema` exactly like Confluence.

## Error handling

Typed `CairnError`s throughout, matching shared rules:
- `CONFIG_INVALID` — `sitePath` missing on disk, or no
  `docusaurus.config.js|ts` found; message names the path, nextAction says
  what to fix in `cairn.json`.
- `NOT_FOUND` — `getPage`/`updatePage` on an id whose file/folder is gone.
- Auto-commit failures are folded into the result as a `warning` string,
  never thrown.

No auth, no rate limits, no HTTP — the error surface is small by design.

## Testing

- **Unit tests** (`docusaurus.unit.test.ts`): temp-dir site fixture (bare
  `docusaurus.config.js` + empty `docsDir`); assert file layout, front
  matter, `_category_.json` content, slug stability across renames,
  idempotent re-publish (second publish → identical tree), ownership
  boundary (files outside the project folder untouched), config validation
  errors, auto-commit on a temp git repo (commit exists, nothing pushed) and
  auto-commit degradation on a non-repo.
- **Contract suite** (`test/docs-contract.ts`): run against the Docusaurus
  adapter on a temp dir, as `contract-docs-fake` does for the fake.
- **Publisher branch**: `publishTree` against the fake with
  `hasNativeToc: true` flipped → no TOC markdown in any page body;
  with `false` → existing snapshot unchanged.
- No live test — there is no remote to hit; the temp-dir unit tests are the
  live tests.

## Out of scope (v1)

- Pushing to a remote, PR creation, or any git networking.
- Attachments/static assets (`hasAttachments: false`; revisit if audit
  screenshots (CRN-24) land in docs publishing).
- Site URL computation for `Page.url` (needs the site's `baseUrl` +
  `routeBasePath`; file paths suffice for v1 output).
- Versioned docs (`versioned_docs/`) and i18n trees.
